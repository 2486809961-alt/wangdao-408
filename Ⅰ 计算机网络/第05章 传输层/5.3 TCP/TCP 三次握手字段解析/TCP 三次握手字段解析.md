## 三、知识点要点（摘自本书解析）

- **第5章 第34题**：TCP中端口号80标识 Web 服务器端的 HTTP进程，客户端访问 Web 服务器HTTP 进程的端口号由客户端的操作系统动态分配。因此答案为选项C。
- **第5章 第35题**：客户端使用的端口号仅在客户进程运行时才动态地选择。应用进程通过端口号进行标识，端口号长度为16位。不同计算机的相同端口号是没有联系的，因此选项D 错误。
- **第5章 第36题**：TCP提供的是一对一全双工可靠的字节流服务，所以 TCP并不支持广播。
- **第5章 第40题**：URG 是紧急位，其为1时表示报文段中有紧急数据，需要尽快发送。RST 是复位位，其为1时表示出现严重错误，必须释放连接，然后重新建立连接。ACK 是确认位，其为1时表示确认字号（ack）字段有效。FIN为终止位，其为1时代表发送方请求释放单向连接，此时并没有完全释放连接，只有当接收方发送完数据并同样将 FIN 位置为1时才会释放连接。
- **第5章 第43题**：两端主机在发出建立TCP连接的请求时，会在TCP 首部写入 MSS（最大报文段长度）选项，告诉对方自己接口能够适应的 MSS的大小，然后在二者之间选择一个较小的值投入使用，此后 TCP将以 MSS的大小对数据进行分割发送。MSS是在三次握手时计算得出。
- **第5章 第48题**：参与TCP 连接的两个进程中的任何一个都能提出释放连接的请求。
- **第5章 第49题**：、CTCP 使用三次握手来建立连接，第一次握手时，A发给BTCP报文中应置其首部 SYN位为1，并选择序号 seq=X，表明传送数据时的第一个数据字节的序号是 X；在第二次握手中，即B接收到报文后，发给 A确认报文段中应使 SYN=1、ACK=1，且序号 ACKX1=1（ACK 下标为捎带序号），同时告诉自己选择的序号seq=Y。
- **第5章 第50题**：在TCP的“三次握手”中，第二次握手时，SYN和ACK均被置为1。
